   52: =head1 DESCRIPTION
   53: 
   54: A subclass of L<Class::Simple> that transparently caches the return values of
   55: getter calls, so that repeated reads of expensive-to-compute or
   56: expensive-to-transport values hit the cache instead of the wrapped object.
   57: 
   58: Cache coherency is I<not> automatic.  If the wrapped object's state changes
   59: through a path other than the cached wrapper, callers must invalidate the cache
   60: themselves.

  333: 
  334: Intercepts every method call that is not explicitly defined, proxying it to
  335: the wrapped object with a caching layer for zero-argument (getter) calls.
  336: 
  337: Setter calls (one or more arguments) always pass through to the wrapped object
  338: and update the cache with the new value.
  339:

  341: 
  342:     $method()        â€” getter: returns cached value if present, else calls object
  343:     $method($scalar) â€” scalar setter: stores scalar, updates cache
  344:     $method(@list)   â€” array setter: stores list, updates cache
  345: 
  346: =head3 RETURNS

  480: =head1 LIMITATIONS
  481: 
  482: =over 4
  483: 
  484: =item Setter arguments are not part of the cache key.
  485: 
  486: Calls like C<< $obj->method($arg) >> use the key C<ClassName:method> regardless
  487: of C<$arg>.  Setters with different arguments therefore overwrite each other's
  488: cache entries.  For read-only caching of parameterised methods, see
  489: L<Class::Simple::Readonly::Cached>.
  490: 
  491: =item Falsy scalar return values are not cached.
  492: 
  493: Methods that return C<0> or C<''> (false but defined) are treated as a cache
  494: miss on every call: the underlying object is re-invoked each time.  Only
  495: C<undef> is cached (via the UNDEF_SENTINEL).  If you need to cache C<0>, wrap
  496: it in a container object or use a different caching strategy.
  497: 
  498: =item Sentinel collision.
  499: 
  500: If the wrapped object ever returns the literal string
  501: C<< "Class::Simple::Cached\>UNDEF\<" >> as a scalar, or as the first element of a
  502: list, the module will misinterpret it as a cached-undef marker.  This string is
  503: deliberately unusual, but callers working with arbitrary string data should be
  504: aware of the constraint.
  505: 
  506: =item Shared cache and multiple classes.
  507: 
  508: When two C<Class::Simple::Cached> instances of B<different> classes share the
  509: same cache object, their keys are namespaced by class name and do not collide.
  510: However, C<purge()> on a CHI-style cache is global: destroying one instance will
  511: purge I<all> entries from a shared CHI cache, including those of the other
  512: instance.  Use per-instance cache objects, or a hash-ref cache, to avoid this.
  513: 
  514: =item Does not work with L<Memoize>.
  515: 
  516: =back
