   55: =head1 DESCRIPTION
   56: 
   57: A transparent caching wrapper for any L<Class::Simple>-compatible get/set object.
   58: Repeated getter calls hit the cache instead of the wrapped object, avoiding
   59: expensive recomputation or remote round-trips.
   60: 
   61: Cache coherency is I<not> automatic.  If the wrapped object's state changes
   62: through a path other than the cached wrapper, callers must invalidate the cache
   63: themselves.
   64:

  372: 
  373: Setter calls (one or more arguments) always pass through to the wrapped object
  374: and update the cache with the new value.

  381: 
  382: =head3 RETURNS

  596: =head1 LIMITATIONS
  597: 
  598: =over 4
  599: 
  600: =item Setter arguments are not part of the cache key.
  601: 
  602: Calls like C<< $obj->method($arg) >> use the key C<ClassName:method> regardless
  603: of C<$arg>.  Setters with different arguments therefore overwrite each other's
  604: cache entries.  For read-only caching of parameterised methods, see
  605: L<Class::Simple::Readonly::Cached>.
  606: 
  607: =item Falsy scalar return values are not cached.
  608: 
  609: Methods that return C<0> or C<''> (false but defined) are treated as a cache
  610: miss on every call: the underlying object is re-invoked each time.  Only
  611: C<undef> is cached (via the UNDEF_SENTINEL).  If you need to cache C<0>, wrap
  612: it in a container object or use a different caching strategy.
  613: 
  614: =item Sentinel collision.
  615: 
  616: If the wrapped object ever returns the literal string
  617: C<< "Class::Simple::Cached\>UNDEF\<" >> as a scalar, or as the first element of a
  618: list, the module will misinterpret it as a cached-undef marker.  This string is
  619: deliberately unusual, but callers working with arbitrary string data should be
  620: aware of the constraint.
  621: 
  622: =item Shared cache and multiple classes.
  623: 
  624: When two C<Class::Simple::Cached> instances of B<different> classes share the
  625: same cache object, their keys are namespaced by class name and do not collide.
  626: However, C<purge()> on a CHI-style cache is global: destroying one instance will
  627: purge I<all> entries from a shared CHI cache, including those of the other
  628: instance.  Use per-instance cache objects, or a hash-ref cache, to avoid this.
  629: 
  630: =item Does not work with L<Memoize>.
  631: 
  632: =item Overloaded C<eq> on cached values.
  633: 
  634: If the wrapped object returns a blessed value that overloads the C<eq> operator,
  635: the sentinel comparison in the getter uses a C<ref()> pre-check so that only
  636: plain strings are compared against the sentinel.  Array elements are subject to
  637: the same pre-check.  Callers wrapping objects that return sentinel-like strings
  638: via overloading should be aware of this guard.
  639:
