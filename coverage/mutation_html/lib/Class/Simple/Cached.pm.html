   56: =head1 DESCRIPTION
   57: 
   58: A subclass of L<Class::Simple> that transparently caches the return values of
   59: getter calls, so that repeated reads of expensive-to-compute or
   60: expensive-to-transport values hit the cache instead of the wrapped object.
   61: 
   62: Cache coherency is I<not> automatic.  If the wrapped object's state changes
   63: through a path other than the cached wrapper, callers must invalidate the cache
   64: themselves.

  505: =head1 LIMITATIONS
  506: 
  507: =over 4
  508: 
  509: =item Setter arguments are not part of the cache key.
  510: 
  511: Calls like C<< $obj->method($arg) >> use the key C<ClassName:method> regardless
  512: of C<$arg>.  Setters with different arguments therefore overwrite each other's
  513: cache entries.  For read-only caching of parameterised methods, see
  514: L<Class::Simple::Readonly::Cached>.
  515: 
  516: =item Falsy scalar return values are not cached.
  517: 
  518: Methods that return C<0> or C<''> (false but defined) are treated as a cache
  519: miss on every call: the underlying object is re-invoked each time.  Only
  520: C<undef> is cached (via the UNDEF_SENTINEL).  If you need to cache C<0>, wrap
  521: it in a container object or use a different caching strategy.
  522: 
  523: =item Sentinel collision.
  524: 
  525: If the wrapped object ever returns the literal string
  526: C<< "Class::Simple::Cached\>UNDEF\<" >> as a scalar, or as the first element of a
  527: list, the module will misinterpret it as a cached-undef marker.  This string is
  528: deliberately unusual, but callers working with arbitrary string data should be
  529: aware of the constraint.
  530: 
  531: =item Shared cache and multiple classes.
  532: 
  533: When two C<Class::Simple::Cached> instances of B<different> classes share the
  534: same cache object, their keys are namespaced by class name and do not collide.
  535: However, C<purge()> on a CHI-style cache is global: destroying one instance will
  536: purge I<all> entries from a shared CHI cache, including those of the other
  537: instance.  Use per-instance cache objects, or a hash-ref cache, to avoid this.
  538: 
  539: =item Does not work with L<Memoize>.
  540: 
  541: =item Overloaded C<eq> on cached values.
  542: 
  543: If the wrapped object returns a blessed value that overloads the C<eq> operator,
  544: the sentinel comparison in the getter uses a C<ref()> pre-check so that only
  545: plain strings are compared against the sentinel.  Array elements are subject to
  546: the same pre-check.  Callers wrapping objects that return sentinel-like strings
  547: via overloading should be aware of this guard.
  548:
